**Solo para el camino «como código».** Si vas a crear la VM desde la interfaz web de Proxmox, salta a
[Crear la máquina](/es/machine/create/).

OpenTofu se ejecuta en **tu portátil** (o, más adelante, en un trabajo de CI) y llega a Proxmox desde
ahí. Antes del primer `tofu apply` necesita cuatro cosas, y ninguna es acceso de root:

| Qué | Para qué | Dónde se guarda |
|---|---|---|
| Un **token de API** de Proxmox con privilegios limitados | Crea y modifica la VM a través de la API de Proxmox | Tu gestor de contraseñas |
| Un **usuario SSH** restringido en Proxmox | Sube el fichero de cloud-init (lo único que la API no puede hacer) | Tu clave SSH, en tu agente SSH |
| Un **bucket** para el estado y sus claves de acceso | Guarda el registro de OpenTofu de lo que ha creado en un sitio más seguro que tu portátil | Las claves, en tu gestor de contraseñas |
| Una **frase de paso del estado** | Cifra el estado antes de que salga de tu portátil | Tu gestor de contraseñas |

El razonamiento detrás de cada elección está en las [preguntas frecuentes](/es/start-here/faq/#capítulo-1--la-máquina).

<Aside type="tip" title="Hazlo con un agente de IA">
La skill `machine` cubre también esta página. Consulta [Usar con un agente de IA](/es/start-here/agents/).
El agente nunca ve tu token, tus claves ni tu frase de paso: los creas y exportas tú.
</Aside>

<Steps>

1. **Instala OpenTofu** en tu portátil ([guía de instalación](https://opentofu.org/docs/intro/install/)) y compruébalo:

   ```sh title="Portátil"
   tofu version
   ```

   Debe mostrar `OpenTofu v1.12.x` o posterior.

   <Aside>¿Prefieres **Terraform**? Los ejemplos funcionan con él sin cambios: escribe `terraform`
   donde la guía escribe `tofu`. La única excepción es el cifrado del estado del paso 5. Terraform
   no lo tiene, así que dependerías del cifrado propio del bucket.</Aside>

2. **Crea un usuario y un token de API de Proxmox.** Solo recibe los privilegios que necesita para
   gestionar VMs, no los de root:

   ```sh title="Host de Proxmox"
   pveum user add tofu@pve --comment "OpenTofu provisioning"
   pveum role add TofuProvisioner -privs "Datastore.Allocate Datastore.AllocateSpace \
     Datastore.AllocateTemplate Datastore.Audit Pool.Audit SDN.Audit SDN.Use Sys.Audit Sys.Console \
     Sys.Modify VM.Allocate VM.Audit VM.Clone VM.Config.CDROM VM.Config.CPU VM.Config.Cloudinit \
     VM.Config.Disk VM.Config.HWType VM.Config.Memory VM.Config.Network VM.Config.Options \
     VM.Console VM.GuestAgent.Audit VM.Migrate VM.PowerMgmt"
   pveum aclmod / -user tofu@pve -role TofuProvisioner
   pveum user token add tofu@pve provider --privsep 0
   ```

   El último comando muestra el secreto del token **una sola vez**. Guárdalo ya en tu gestor de
   contraseñas, junto con su **id de token**, `tofu@pve!provider`. OpenTofu necesita los dos, con
   el formato `tofu@pve!provider=<secreto>`.

   <Aside>Si más adelante `tofu apply` falla con `Permission check failed (…, <PRIVILEGIO>)`, añade
   ese privilegio con `pveum role modify TofuProvisioner -append 1 -privs <PRIVILEGIO>`. Los nombres
   de los privilegios cambiaron en Proxmox 9.</Aside>

3. **Crea un usuario SSH restringido en Proxmox.** El proveedor sube el fichero de cloud-init por
   SSH, porque la API de Proxmox no permite subir «snippets». Este usuario de Linux puede hacer
   **solo** eso: puede ejecutar dos comandos exactos como root, y nada más. (No tiene nada que ver
   con el usuario de API `tofu@pve` de arriba.)

   Sustituye `<YOUR_SSH_PUBLIC_KEY>` por tu clave **pública**: el contenido de
   `~/.ssh/id_ed25519.pub`, o el campo *Public key* si tu clave vive en un gestor de contraseñas
   (ver la nota de abajo). El primer comando instala `sudo`, que Proxmox no trae:

   ```sh title="Host de Proxmox"
   apt install -y sudo
   useradd -m -s /bin/bash tofu
   install -d -m 700 -o tofu -g tofu /home/tofu/.ssh
   echo '<YOUR_SSH_PUBLIC_KEY>' > /home/tofu/.ssh/authorized_keys
   chown tofu:tofu /home/tofu/.ssh/authorized_keys && chmod 600 /home/tofu/.ssh/authorized_keys
   cat > /etc/sudoers.d/tofu <<'EOF'
   tofu ALL=(root) NOPASSWD: /usr/sbin/pvesm apiinfo
   tofu ALL=(root) NOPASSWD: /usr/bin/tee ^/var/lib/vz/snippets/[a-zA-Z0-9_][a-zA-Z0-9_.-]*$
   EOF
   chmod 440 /etc/sudoers.d/tofu && visudo -c
   ```

   La primera regla es como el proveedor comprueba que sudo funciona. La segunda le deja escribir un
   fichero en la carpeta de snippets del almacenamiento `local`, y en ningún otro sitio.
   (`/var/lib/vz` es donde vive `local`. Si tus snippets van a otro almacenamiento, usa su ruta de
   `pvesh get /storage/<nombre>`.)

   Compruébalo desde tu portátil. El primer comando debe listar tu clave (está cargada en tu agente
   SSH). El segundo debe mostrar una línea `APIVER` sin pedir contraseña:

   ```sh title="Portátil"
   ssh-add -l
   ssh tofu@proxmox.home.example.com sudo pvesm apiinfo
   ```

   <Aside title="¿Clave SSH en un gestor de contraseñas?">
   Algunos gestores de contraseñas (Bitwarden, 1Password) guardan la clave privada en la bóveda y
   hacen de agente SSH, así que la clave nunca está en disco. Activa el agente en la aplicación de
   escritorio, apunta `SSH_AUTH_SOCK` al socket que indique su documentación y compruébalo con
   `ssh-add -l`. La preparación de la VM, en la página siguiente, lee tu clave pública de un
   **fichero**, así que guarda también la mitad pública:

   ```sh title="Portátil"
   ssh-add -L > ~/.ssh/homelab.pub
   ```

   Si `ssh-add -L` muestra varias claves, deja en ese fichero solo la línea correcta. Una clave
   pública no es secreta.
   </Aside>

   <Aside type="caution">Nunca amplíes estas reglas a los comandos `pvesm` o `qm` completos, ni a
   `tee` con un `*`. Cualquiera de ellos equivale a ser root.</Aside>

4. **Crea un bucket para el estado.**

   <Tabs syncKey="state-bucket">
   <TabItem label="Cloudflare R2">

   R2 es el almacenamiento compatible con S3 de Cloudflare. El estado ocupa unos pocos kilobytes,
   muy dentro del plan gratuito, pero la primera vez que activas R2 te pide un método de pago.

   1. En el panel de Cloudflare, abre **R2 Object Storage** y pulsa **Create bucket**. Llámalo
      `homelab-tofu-state` y deja la ubicación en automática.
   2. En la vista general de R2, abre **Manage API tokens → Create API token**:
      - Permisos: **Object Read & Write**.
      - Alcance: **Apply to specific buckets only**, y elige `homelab-tofu-state`.
   3. Cloudflare muestra un **Access Key ID** y un **Secret Access Key** una sola vez. Guarda los dos
      en tu gestor de contraseñas.
   4. Copia el endpoint **S3 API** del bucket desde sus ajustes. Tiene la forma
      `https://<YOUR_CLOUDFLARE_ACCOUNT_ID>.r2.cloudflarestorage.com`, o con `.eu.` antes de `r2`
      si elegiste la jurisdicción de la UE. Úsalo tal cual aparece. No es secreto.

   </TabItem>
   <TabItem label="Otro almacenamiento compatible con S3">

   Sirve cualquier servicio compatible con S3: Amazon S3, Backblaze B2 u otro proveedor. Crea un
   bucket privado y una clave de acceso que pueda leer y escribir **solo en ese bucket**. Apunta su
   endpoint y su región. El fichero `backend.hcl.example` del ejemplo muestra qué cambiar.

   Evita un bucket alojado en el propio homelab, al menos para este estado. El estado describe la
   máquina, así que no debería vivir en esa misma máquina.

   </TabItem>
   </Tabs>

5. **Elige una frase de paso para el estado.** Genera en tu gestor de contraseñas una frase de paso
   larga y aleatoria (16 caracteres como mínimo) y guárdala allí.

   <Aside type="danger">Sin la frase de paso, el estado no se puede descifrar. OpenTofu deja de saber
   que gestiona la VM, y tendrías que volver a importarla a mano. Guárdala en tu gestor de
   contraseñas, no solo en tu memoria.</Aside>

</Steps>

## Cómo llegan los secretos a OpenTofu

No pones los cuatro secretos en ningún fichero. Cada vez que trabajas con OpenTofu, los cargas en
la terminal con `load-secrets.sh`, un pequeño script de la carpeta del ejemplo. Te pide cada valor
sin mostrarlo en pantalla. Pegas cada uno desde tu gestor de contraseñas, y el script los exporta
como las variables de entorno que lee OpenTofu:

| Pregunta | Variable | Quién la lee |
|---|---|---|
| Proxmox API token | `PROXMOX_VE_API_TOKEN` | El proveedor de Proxmox |
| State bucket: Access Key ID | `AWS_ACCESS_KEY_ID` | El backend S3 |
| State bucket: Secret Access Key | `AWS_SECRET_ACCESS_KEY` | El backend S3 |
| State passphrase | `TF_VAR_state_passphrase` | El cifrado del estado |

No se escribe nada en disco ni en el historial de la terminal, y los valores desaparecen al cerrarla.
Lo ejecutarás en la página siguiente.

## Dónde estás ahora

- [x] OpenTofu instalado.
- [x] Cuatro secretos en tu gestor de contraseñas: el token de API de Proxmox, las dos claves de
      acceso del bucket y la frase de paso del estado.
- [x] `ssh tofu@<proxmox-host> sudo pvesm apiinfo` muestra `APIVER` sin pedir contraseña.
- [x] Tu clave pública en un fichero de tu portátil.

En Proxmox todavía no existe nada aparte de los usuarios. **Siguiente:** [Crear la máquina](/es/machine/create/),
pestaña OpenTofu. Allí pones el código del ejemplo en tu repositorio, rellenas tus valores, cargas
los secretos y ejecutas `tofu plan`.
