From this chapter on, you stop changing the cluster by hand. You change files in your private
repository and push, and **ArgoCD** makes the cluster match. At the end you'll have:
- **ArgoCD** running in the cluster, at a pinned version,
- read-only access to your private repository, with a **deploy key**,
- a **root app** that turns each file in `apps/` into an app ArgoCD runs ("app of apps"),
- ArgoCD **managing its own install** from the repository, so upgrading it is a commit,
- a small demo app that you change and then remove, through git alone.

</Aside>

**Tested with:** ArgoCD v3.6.1 (Helm chart 10.12.1) on k3s v1.37.2+k3s1, helm 4.3.

## A few ideas first

### GitOps
Your repository says what should run. **ArgoCD** runs in the cluster, reads the repository, compares
it with what's running, and **syncs** the difference. Two settings make git the only way in:
- **prune:** something removed from git is removed from the cluster,
- **self-heal:** something changed by hand in the cluster is changed back to what git says.

So you get a history of every change, a revert button (`git revert`), and a cluster you can rebuild
by pointing a new ArgoCD at the same repository.

### Applications and the "app of apps"
ArgoCD's unit is an **Application**: "take this folder (or Helm chart) and put it in the cluster".
An Application is itself a small YAML file, so ArgoCD can manage Applications too. You create one
**root** Application by hand. It watches the `apps/` folder, and every file there is the
Application for one app. Adding an app is adding a file.

```text
your-config-repo/
├── bootstrap/                   done once, by hand
│   ├── root.yaml                the root Application
│   └── add-repo-key.sh          gives ArgoCD read access to the repository
├── apps/                        one Application per app; the root watches this folder
│   ├── argocd.yaml              ArgoCD itself
│   └── hello.yaml               the demo app
└── manifests/                   what each app runs
    ├── argocd/values.yaml       settings for ArgoCD's Helm chart
    └── hello/hello.yaml         the demo app's Kubernetes files
```

### ArgoCD manages itself
You install ArgoCD once with **Helm**, from your laptop. Then `apps/argocd.yaml` points ArgoCD at
the same chart, version and values file, and ArgoCD takes over its own install. After that,
upgrading ArgoCD or changing its settings is a commit, like any other app.

The reasoning behind each choice is in the [FAQ](/start-here/faq/#chapter-3--gitops).

## Set it up

<Steps>

1. **Add the files to your repository.** Copy the contents of
   [`examples/03-gitops`](https://github.com/romansegador/homelab-guide/tree/main/examples/03-gitops)
   to the root of your private repository: `apps/`, `bootstrap/` and `manifests/`. Run this chapter's laptop commands from your repository's root folder.

   Then fill in two values:
   - In `bootstrap/root.yaml`, `apps/argocd.yaml` and `apps/hello.yaml`, replace
     `<YOUR_CONFIG_REPO_URL>` with your repository's **SSH** address, for example
     `git@github.com:<YOUR_GITHUB_USER>/<YOUR_CONFIG_REPO>.git`. GitHub shows it under
     *Code → SSH*.
   - In `manifests/argocd/values.yaml`, set `domain` to the address ArgoCD will have in chapter 5,
     for example `argocd.lab.home.example.com`.

   Commit and push to `main`: ArgoCD reads the repository from GitHub, not from your laptop. If
   you work with pull requests, merge it before step 5.

2. **Install ArgoCD** with Helm, at the version pinned in `apps/argocd.yaml`:

   ```sh title="Laptop"
   helm repo add argo https://argoproj.github.io/argo-helm
   helm repo update argo
   helm install argocd argo/argo-cd --version 10.12.1 --namespace argocd --create-namespace --values manifests/argocd/values.yaml
   kubectl -n argocd wait --for=condition=Available deployment --all --timeout=300s
   ```

   The last command waits until every part of ArgoCD is up, usually within a minute or two.

3. **Give ArgoCD read access to your repository.** The script makes a new SSH key, stores its
   private half in the cluster without showing it, and prints the public half:

   ```sh title="Laptop"
   bash bootstrap/add-repo-key.sh git@github.com:<YOUR_GITHUB_USER>/<YOUR_CONFIG_REPO>.git
   ```

   On GitHub, open your repository's *Settings → Deploy keys → Add deploy key*. Paste the public
   key, name it `argocd`, and leave **Allow write access** unticked.

   There's nothing to save in your password manager. If you lose the key or rebuild the cluster,
   run the script again and replace the deploy key on GitHub.

4. **Open the web UI.** Copy the admin password to your clipboard and save it in your password
   manager as "ArgoCD admin (lab-1)":

   ```sh title="Laptop"
   kubectl -n argocd get secret argocd-initial-admin-secret -o jsonpath='{.data.password}' | base64 -d | pbcopy
   ```

   Then forward a local port to ArgoCD. Leave this running in its own terminal:

   ```sh title="Laptop"
   kubectl -n argocd port-forward service/argocd-server 8080:443
   ```

   Open [https://localhost:8080](https://localhost:8080) and log in as `admin` with that password.
   The browser warns about the certificate: ArgoCD uses a self-signed one until chapter 5. Accept
   it for `localhost`. The UI is empty for now.

5. **Hand the cluster over to git.** Create the root Application, the only one you create by
   hand:

   ```sh title="Laptop"
   kubectl apply -f bootstrap/root.yaml
   kubectl -n argocd get applications
   ```

   In a minute, three Applications show `Synced` and `Healthy`: `root`, `argocd` and `hello`. Run
   the second command again until they do, or watch them appear in the UI. If an Application shows
   an error about the repository, check the deploy key from step 3.

   From now on, ArgoCD manages its own install. Don't run `helm upgrade` on it again: to change
   ArgoCD, edit `manifests/argocd/values.yaml` or the version in `apps/argocd.yaml`, and push.

</Steps>

## Check it

**The demo app runs:**

```sh title="Laptop"
kubectl -n hello get pods
```

One `hello` pod is `Running`.

**Self-heal reverts changes made by hand.** Scale the app to 3 copies with kubectl:

```sh title="Laptop"
kubectl -n hello scale deployment hello --replicas=3
kubectl -n hello get deployment hello
```

Run the second command again after a few seconds: ArgoCD has put it back to `1`, because that's
what git says.

**A commit changes the cluster.** In `manifests/hello/hello.yaml`, change `replicas: 1` to
`replicas: 2`, then commit and push. ArgoCD checks the repository every 3 minutes. To skip the
wait, click **Refresh** on the `hello` app in the UI. Then:

```sh title="Laptop"
kubectl -n hello get pods
```

Two pods are `Running`.

**Removing a file removes the app.** Delete `apps/hello.yaml` and the `manifests/hello/` folder,
then commit and push. After the next sync (or a **Refresh** on `root`), the `hello` app and its
namespace are gone:

```sh title="Laptop"
kubectl -n argocd get applications
kubectl get namespace hello
```

The first lists only `root` and `argocd`. The second says the namespace is `NotFound`.
