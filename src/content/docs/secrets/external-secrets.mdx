Apps need passwords, API keys and tokens. They can't go in git, not even in a private repository,
but ArgoCD only applies what's in git. This chapter solves that: the secrets live in **Bitwarden
Secrets Manager**, and **External Secrets** copies them into the cluster as Kubernetes Secrets. Git
holds only *which* secret an app needs, never its value. At the end you'll have:
- a Bitwarden project for the cluster, and a **machine account** that can read it,
- **External Secrets** and **cert-manager** installed by ArgoCD, from your repository,
- one **ClusterSecretStore** that every namespace can use,
- a demo secret that follows Bitwarden when you change it there.

v1.37.2+k3s1 with ArgoCD 3.6.1.

## A few ideas first

### The pieces
```text
Bitwarden Secrets Manager                       your cluster
┌──────────────────────┐   machine account   ┌────────────────────────────────────────────┐
│ project "lab-1"      │◀──── access token ───│ ClusterSecretStore "bitwarden"             │
│   demo-message = …   │                      │   ▲                                        │
│   db-password  = …   │                      │ ExternalSecret: "I need demo-message"      │
└──────────────────────┘                      │   ▼                                        │
                                              │ Secret "demo" (what the app actually reads)│
                                              └────────────────────────────────────────────┘
```

- A **project** in Bitwarden Secrets Manager holds the cluster's secrets. A **machine account** is
  a non-human user with read access to that project, and its **access token** is how the cluster
  logs in.
- A **ClusterSecretStore** says "this is how to reach Bitwarden". You write it once.
- An **ExternalSecret** says "make a Kubernetes Secret with these values from the store". It names
  secrets, so it's safe in git, and each app gets its own.
- External Secrets checks Bitwarden on a schedule and keeps each Secret up to date.

### The one secret you create by hand
The cluster needs the machine account's token *before* it can read anything from Bitwarden, so
that token can't come from Bitwarden. You put it in the cluster once, with a script that asks for it
with hidden input. Every other secret comes from Bitwarden.

### Why cert-manager appears here
External Secrets talks to Bitwarden through a small helper inside the cluster, the **Bitwarden SDK
server**, and that helper only speaks HTTPS. **cert-manager** makes its certificate. Chapter 5
uses cert-manager again, for real HTTPS certificates.

The reasoning behind each choice is in the [FAQ](/start-here/faq/#chapter-4--secrets).

## Set it up

<Steps>

1. **Prepare Bitwarden Secrets Manager.** In the Bitwarden web app, open **Secrets Manager** from
   the product switcher. The first time, you create or choose an organization for it. Then:
   1. **Projects → New project**, named after your cluster, for example `lab-1`.
   2. **Secrets → New secret**: name `demo-message`, value `hello from Bitwarden`, project `lab-1`.
   3. **Machine accounts → New machine account**, named `lab-1`. In its **Projects** tab, add
      `lab-1` with **Can read**.
   4. In the machine account's **Access tokens** tab, create a token. Bitwarden shows it once: save
      it in your password manager as "Bitwarden SM token (lab-1)".

   Note two ids. They aren't secret: without the token they give access to nothing.
   - The **organization id** is in the address bar: `…/sm/<ORGANIZATION_ID>/…`.
   - The **project id** is in the address bar when you open the project:
     `…/projects/<PROJECT_ID>/…`.

2. **Put the access token in the cluster.** Copy
   [`examples/04-secrets`](https://github.com/romansegador/homelab-guide/tree/main/examples/04-secrets)
   into your private repository, merging its `apps/`, `bootstrap/` and `manifests/` folders into
   the ones from chapter 3. Then run the script, and paste the token when it asks:

   ```sh title="Laptop"
   bash bootstrap/add-bitwarden-token.sh
   ```

   This goes first so the token is waiting when External Secrets starts.

3. **Fill in your values, and push.**
   - In `apps/secrets-config.yaml` and `apps/secret-demo.yaml`, replace `<YOUR_CONFIG_REPO_URL>`
     with your repository's SSH address, as in chapter 3.
   - In `manifests/secrets-config/cluster-secret-store.yaml`, set `organizationID` and
     `projectID`. If your Bitwarden account is on the EU cloud (you log in at `vault.bitwarden.eu`),
     change two lines in the same file: `apiURL` to `https://api.bitwarden.eu`, and `identityURL`
     to `https://identity.bitwarden.eu`. Leave `bitwardenServerSDKURL` as it is: it points to the
     helper inside your cluster.

   Commit and push to `main`. ArgoCD picks up the four new files in `apps/` within 3 minutes, or
   click **Refresh** on `root` in the UI.

4. **Watch it come up.** ArgoCD installs cert-manager and External Secrets, then the certificate
   and the store. The store's first sync can fail while the other two are still installing:
   ArgoCD retries on its own. After a few minutes:

   ```sh title="Laptop"
   kubectl -n argocd get applications
   kubectl get clustersecretstore bitwarden
   ```

   Every Application is `Synced` and `Healthy`, and the store shows `Valid` and `READY` `True`.

</Steps>

## Check it

**The secret arrived:**

```sh title="Laptop"
kubectl -n secret-demo get externalsecret demo
kubectl -n secret-demo get secret demo -o jsonpath='{.data.message}' | base64 -d; echo
```

The ExternalSecret shows `SecretSynced`, and the second command prints `hello from Bitwarden`.

**It follows Bitwarden.** In Bitwarden, change `demo-message` to `hello again`. The demo checks
every minute, so within a minute the second command above prints `hello again`.

**Git doesn't hold the value.** Open `manifests/secret-demo/secret-demo.yaml`: it names
`demo-message`, and the value is nowhere in your repository.

**Remove the demo.** Delete `apps/secret-demo.yaml` and `manifests/secret-demo/`, commit and push.
After the next sync, the `secret-demo` namespace and its Secret are gone:

```sh title="Laptop"
kubectl get namespace secret-demo
```

It says `NotFound`. You can delete `demo-message` in Bitwarden too.

## Before you move on
